# 校准回测脚手架（P2 · 只搭架子，不含数据）

> 目的：为「算法判定 ↔ 已证实生平」的人工校准回测提供固定结构。**本目录不收集任何命例数据**——
> 仓库里只有 schema、空白模板和 runner 骨架；命例由维护者自行添加、自行保管（含真实生辰，勿入库，
> `.gitignore` 已排除 `*.case.json`）。

## 文件

| 文件 | 作用 |
|---|---|
| `case-schema.json` | 命例文件的 JSON Schema（生辰 + 已证实生平事件年表 + 四个模块评分维度） |
| `case-template.json` | 空白命例模板（复制为 `<名字>.case.json` 后填写） |
| `run-calibration.ts` | runner 骨架：读命例 → 算法层排盘 → 输出待人工评分的对照表（Markdown） |
| `career-mapping.schema.json` | 十神→现代职业映射库的**空 schema 占位**（内容另行立项，本轮不填） |
| `classics/` | **典籍命例库**（`case_type: 典籍判定`，金标=书上判定，无隐私、入库当回归）。首批韦千里 7 例与试点对照表见 `classics/README.md` |

## 用法

1. 复制 `case-template.json` 为 `张三.case.json`，填入生辰与**已证实**的生平事件年表（换工作 / 搬家 /
   结婚 / 大病 / 破财等，只填当事人确认过的，不填推测）。
2. 跑 runner（开发环境）：

   ```bash
   npx tsx run-calibration.ts                # 扫描本目录全部 *.case.json
   npx tsx run-calibration.ts --output=calibration-report.md
   ```

3. 得到的对照表按四个模块并列「算法判定 | 命例事实 | 评分(空)」：
   - **用神**：算法用神出口 vs 当事人自述有效/无效的方向；
   - **大运应期**：运岁引动建议节点 vs 事件年表逐年对照（命中/偏移1年内/未命中）;
   - **婚恋画像**：正缘倾向判定(年龄/宫坐) vs 实际配偶情况；
   - **职业方向**：财路链判定所需的十神结构摘要 vs 实际职业（映射库未建，先人工判）。
4. 人工在「评分」列打 0/0.5/1 并统计——**评分标准与汇总方法由维护者定，runner 不代打分**。

## 边界

- runner 只读命例、只产对照表；不改盘、不写库、不联网。
- 命例文件含真实生辰属敏感数据：只放本地，不提交，不用于示例。
