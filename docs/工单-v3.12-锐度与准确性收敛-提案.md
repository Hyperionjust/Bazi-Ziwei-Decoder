# 工单提案 · v3.12/v3.13 锐度与准确性收敛（待作者拍板）

> 提案日：2026-07-30。依据：`_scratch/调查-待立项五线头-2026-07-30.md` + `_scratch/质检-v3.11-全链路-2026-07-30.md`（两份都有量化数据，本单只引结论）。
> 一句话主题：**v3.11 把「能力」建完了，v3.12 把「天平」调准**——现在系统性偏保守（79.5% 盘被判 low、韦例 7 盘 0 张 high），根因一半在 confidence 口径、一半在旺衰计分自身，两者必须一起调、一起回归。

## 一、总体设计

**两个版本、五个批次。** v3.12 = 用户可感知的锐度修复（A+B+E，小而准）；v3.13 = 判定层深耕（C+D，量大但有金标网）。
每批一个新会话、独立验收（沿用 v3.11 纪律）；排盘算法层继续一字不动。

```
A 旺衰计分v2+confidence收紧 → B 轴冲突扩义+条例前提 → E 小修清单(顺手) ⇒ 发版 v3.12.0
C 调候层精修(取干13格+词表v2+72条回收) → D S2命例扩量15~20例 ⇒ 发版 v3.13.0
```

**为什么 A 必须在最前**：口径(confidence)和计分(旺衰)是同一架天平的两端——只收口径不修计分，是把「测不准」藏起来；只修计分不收口径，用户看不到任何变化。C/D 依赖 A 定稿后的旺衰基线（否则 13 格核对与新命例的对照结论会跟着计分再变一次，白做）。

## 二、批次明细

### 批A · 旺衰计分 v2 + confidence 口径收紧（≈半个会话批次，风险最高、收益最大）

**A1 计分修正**（`wang-shuai.ts`，梅兰芳例金标：韦断「全局木火太旺」，现判中和 -0.1）：
1. **得势通根加成**：透干且通根者不再吃 +0.7 平权分（梅例双甲正印通根卯只各得 +0.7，印重生身合力被系统性低估）。建议形态：透干+本气根 ×1.8、透干+中余气根 ×1.4，系数由 7 韦例+毛盘联调定值。
2. **得令火库月复核**：戌月对丁火判 -2（本气戊 -3 +余气丁 +1）过狠——火库藏根的「墓库通根」价值单列复核；只动「日主五行在库」的格子，其余月令计分不碰。

**A2 口径收紧**（`confidence.ts` + `yongshen.ts` 边界盘定义）：
1. 边界盘触发条件删去「旺衰置信=中」这一项（保留：低 / 扶抑临界 / 从格分歧 / 格局置信低）；
2. **总档聚合改为「四维取最低」**——「四维全非 low 而总档 low」的矛盾结构性消失，`aggregateConfidenceTier` 的 v1 兼容注释同步改写（这是显式行为变更，不是回归）；
3. 锚点保守声明触发条件：任一维度=low 才出（bazi-prompt「置信度传播」同步）。

**验收（金标全部现成）**：
- 梅例 verdict 进入 偏旺/身强 侧（韦断方向），score 明细逐项留档；
- 7 韦例 tier 分布 ≥3 张 medium/high 且 **0 张方向性回退**（S1-3 的 6✅1◐ 对照必须原样保持——阎/许/马身弱侧 verdict 不得漂移，断言锁）；
- 200 随机盘（固定种子）low 率落入 **35%~50%** 区间断言；
- `npm test` 13 项全绿——**预告：test-shunni 吴锚与 test-boundary 部分断言必然要重祝福**，每处重祝福须写「为什么新值才是对的」（v3.11 的纪律），严禁静默改值。

### 批B · 轴冲突扩义 + 条例旺衰前提（小批，独立可验）

## 三、铁律（全程）

1. 排盘算法层（yiqi-core）一字不动；2. 改任何 `.ts` 后 `npm run bundle`；3. 每批 `cd calculator && npm test` 13 项全绿才准 commit；4. 一切重祝福必须带「为什么新值对」的说明；5. 每批一个新会话，交接靠工单+git+fixtures，不靠会话记忆；6. 身弱侧韦例三盘（阎/许/马）出口逐字回归——批A 动旺衰绝不许把 S1-3 的战果改回去。
