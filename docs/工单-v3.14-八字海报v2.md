# 工单 · v3.14 八字海报 v2：确定性能力可视化

> 立项日：2026-08-01。状态：**G1/G2/G4 完成；G3 自动门禁与样张完成，待作者肉眼确认后发版**。
> 一句话主题：**让海报看见算法已经会的东西，并让小白无需追问就能看懂；确定性字段由渲染层直出，正向语义逐处绿色粗体。**

---

## 一、已拍板的产品取舍

- 五项能力都进入 v2，但采用“两个紧凑块 + 三个条件内联”，不把长图机械加长：
  1. 独立紧凑块：调候“典出”、裁决/轴冲突“核心看点”；
  2. 条件内联：timeline 的 `⏳`、有流月数据时的 12 月风向条、大运/流年的护体档第二维。
- 财路“经营/博弈”继续留在 `career_html`，本版不增加视觉标签。
- 保持现有 analysis schema；新结构默认全部由 `chart.json → render.ts` 投影。只有确实无法由算法字段表达的用户文案才允许新增**可选** analysis 字段，本工单默认没有这种字段。
- 保留水墨底色与命盘主体，但四类海报统一加入纸本肌理、回纹与印章红；综合/八字/紫微/MBTI 同步采用小白阅读引导和正向语义全标绿规则。

---

## 二、字段所有权与呈现契约

| 能力 | 唯一事实源 | 呈现 | 缺省行为 |
|---|---|---|---|
| 典出 | `调候条例.命中` | 按命中数组原序最多取 3 条：条例名 + 克制档位文案 + 原有意象的安全节选；不展示内部 id/判定式 | 无命中则整块隐藏 |
| 核心看点 | `出口.相神裁决`、`出口.轴冲突` | 最多 2 枚徽章；用用户语言写“为何例外/为何两面”，不露字段名和机制词 | 两者皆无则整块隐藏 |
| ⏳引爆 | 当前海报关系视图（有 `作用关系.lineage` 则用其 items，否则用 open items）+ analysis timeline 年份 | 只给已入选的五个 timeline 节点加标记；不强换节点、不添加第六项 | 无同年交集则不标，关系区仍保留窗口 |
| 流月条 | `流月引动` | 12 个节气月的顺/平/逆紧凑条 + 最顺/最逆窗口 | chart 未带流月、或年份与 render 年份不一致则隐藏并告警 |
| 护体档 | `运岁引动.顺逆[].体档` | 在大运/流年方向标记旁增加强/中/弱第二维 | 无体档时保持 v1 单维布局 |

特别约束：`振幅(静/动/剧动)` 与 `体档(强/中/弱)` 是两件事。现有 render 虽计算 `amp_label` 但模板未使用，本版不得拿振幅冒充护体档；是否另显振幅不在本工单范围。

## 三、执行批次

### G1 · 规格与布局定稿

1. 先修现有规格漂移：保留提示词所载的用户质量线，把 `spec.json` 从 160 提到 200，并将四大段统一为“≥6 句、≥200 字、不设上限”；同步 SKILL、bazi-poster、review，并让 `test-spec-sync` 同时核句数、字数与“不设上限”，不再只搜到“6~10”就假绿。四份现有八字金标均已超过 200 字，升级门槛不需要为样例重写而降级。
2. 在 `spec.json` 增加算法所有块的数量、截断和条件显示规则；明确 `owner=algorithm` 的块不要求提示词产出。
3. 产出版式草图：典出和看点共享一行/相邻卡片；流月条、体档嵌入现有运岁区；⏳只改节点图标。确认窄屏、长名称、三条典出和双徽章极限态不溢出。

**产物**：本工单内回填定稿说明即可，不额外制造一份会漂移的设计文档。

### G2 · 确定性渲染接线

1. `chartToFlatBazi` 生成完整可选 HTML 片段，模板只放整块占位符；空字符串即无 DOM，禁止用 `-` 占位造成空卡片。
2. 典出只读取命中条例，展示名不得来自 LLM；档位固定映射为“传统论法偏有利/中性/偏受限/提醒避开”，不写宿命断语。意象只做 HTML 转义和字符上限截断，不调用 LLM“润色”，所有 chart 字符串写入 HTML 前统一转义。
3. 核心看点使用固定白话映射，不直接透出“相神裁决/轴冲突/扶抑忌”等施工词。
4. timeline 标记在 analysis 与 chart 合并后按年份匹配；只标现有 5 项。重复命中的同年合并为一个 `⏳`，详情留在关系区。
5. 流月条要求 chart 的目标年与 `render --currentYear` 一致；不一致时隐藏并向 stderr 输出一次 warning，绝不把旧年数据标成今年。
6. 护体档读取算法层现成 `体档`；方向与护体用形状/文字双编码，不能只靠红绿，兼顾灰阶与色觉差异。

### G3 · 门禁、兼容与视觉验收

1. `check-template` 增加五项必需整块占位符与标签平衡检查；最终 HTML 的残留占位符由 `test-golden` 检查。后者还要明确断言每个条件块的出现/隐藏，不只检查 HTML 能打开。
2. `check-analysis` 保留现有条例引用防编造，因新区块由算法生成，不新增同名 LLM 字段与重复校验。
3. 兼容矩阵：
   - 旧 analysis + 新 chart + 新模板可渲染；
   - 新模板遇旧 chart（无新字段）与无 analysis 均不崩；既有叙事字段沿用 v1 缺省行为，五个新增可选块不得留下空 wrapper；
   - 有/无 `--currentYear`、年份匹配/不匹配均有正反例；
   - 切换 `--lineage` 不改变 open 中立 `作用关系.items/policy_note`；⏳与关系表可共同切换到所选流派视图，二者必须始终同源。
4. 特性矩阵至少三盘：1991 质检盘（轴冲突/条例/流月）、蒋或吴盘（相神裁决）、含半局引爆窗口的公开或合成盘。单一“全能盘”不得代替正反例。
5. 自动门禁查 DOM、字段与溢出；另生成桌面宽度和窄屏截图供肉眼验收，截图放 `_scratch` 或临时产物，不把跨平台像素图当稳定金标提交。

### G4 · 四类海报小白化与正向语义全覆盖（用户追加）

1. 四类模板统一加入纸本肌理、回纹、印章红、小白阅读说明与窄屏适配；章节名改成直接对应现实问题的白话标题。
2. 四份提示词与 SKILL 同步要求：优势、能力、好性格、适配方向、助力、顺风/上行窗口、改善与收益逐处 `hl-good`，不是每段选一两句；正负混合句拆开着色。
3. 八字四大段每段至少 3 处绿色仅作机器底线；综合主轴/阶段段、紫微与 MBTI 各段另设最低存在门。体检器先移除已标绿内容，再扫描剩余普通正文的高置信正向词，漏标即 FAIL。
4. 四份随包 analysis 和最终 HTML 样例全部重制，确保用户看到的示例本身也体现高密度绿色粗体，而不是只更新后台规则。
5. 十神修复早期“一句话”遗漏：机制段恰好 1 句，白话段升级为 ≥6 句、≥200 字、不设上限，并完整回答能力与内在需要、决策与协作、工作落点、发挥收益、过度代价和行动建议。
6. 新增独立“罕见现象”板块：算法层负责罕象名称、罕见度、涉及柱；解读层逐项给出“偏正向／偏提醒／两面性”、现实表现和建议。罕见不等于吉或凶，无罕象时零 DOM。

## 四、发布门

- 五项能力各有“出现 + 隐藏”断言；旧 analysis、新旧 chart 兼容矩阵全绿。
- 页面无 `{{...}}`、`undefined/null`、空标题、空卡片；窄屏无横向溢出，长图分页/截图不断块。
- `npm test` 全绿；源码与 dist-bundle 渲染结果一致；示例 analysis 不因无新字段而重制，只有样例 chart/HTML 因确定性新区块按需刷新。
- 作者肉眼通过三张特性样张后才发 v3.14.0。

## 五、明确不做

- 不新增破坏性的 analysis schema v2；新增字段仅为可选的 `rare.reading_html`。不让 LLM 生成罕象名称/罕见度、条例名、裁决类型、引爆年、流月方向或体档。
- 不显示 confidence 内部机制；只让既有分维规则影响措辞。
- 不加财路性质视觉标签；不做身弱侧降忌权；四类海报只统一视觉语言和阅读规则，不重排紫微十二宫、八字四柱等算法主体。
