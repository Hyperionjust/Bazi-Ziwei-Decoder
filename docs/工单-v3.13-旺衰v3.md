## 二、成功标准与接口边界

### 2.1 发布门

- 三个真正扶抑错向例（顾/阮/周）必须 **3/3 进入弱侧**；郑正秋不要求扶抑分翻向，校准报告必须并列呈现“扶抑结果 + 调候命中”。
- v3.12 的 14✅ **零方向回退**；4◐ 不得恶化为方向相反；旺衰 v2 的既有 12 盘语义断言全部保持。
- `--lineage` 任取 `ziping/ditian/shenfeng/mangpai/open`，同一四柱的 `旺衰`、中立 `作用关系.items/policy_note`、`confidence_tier` 必须逐字一致；允许新增的 `作用关系.lineage` 子视图不同，且只能影响解读。
- 5000 个合法生辰盘（两个预先固定种子各 2500）审计同时输出旺衰五档、confidence 三档和五类日主分布；总档 low 率仍在 `[12%,35%]`，任一五行日主的单档占比相对 v3.12 基线漂移不得超过 15 个百分点。因这 5000 盘没有逐盘旧版快照，v3.12 基线须从同盘旧五项账本 `得令+长生+得地+得势+会局` 重建 v2 score/verdict/confidence，并以该 v2 身势重跑调候、用神与总档 confidence；不得用 `interactions=[]` 冒充基线，因为那只关闭 F2、F1 仍会运行。
- `npm test` 全绿、`dist-bundle` 重建、三份随包样例逐行核；没有通过 F0 证据门则本版停在研究报告，不进入 F1/F2、不发版。

### 2.2 数据与接口

- `WangShuaiResult.breakdown` 只做向后兼容加字段：新增 `耗方群势`、`冲根修正`，并在 `details` 中保留柱位、原始贡献、裁决状态、折损值；既有 `得令/长生/得地/得势/会局` 不删不改名。
- `enrichBazi` 显式接收 open 中立 `interaction_policy`，在内部先裁决关系、再算旺衰，并把同一份裁决挂入 `enrichment.作用关系`；不得先算旺衰后补关系，也不得重复计算两份 open 结果。
- `run-chart` 在 enrich 前一次性加载 `lineages.json`；缺少或无效的 open policy 视为确定性输入缺失，清晰报错并停止，不静默退化成另一套旺衰。
- 不新增泛化的“调候性弱”布尔值或分数。郑正秋由现有 `调候条例.命中/档位计/意象` 表达；校准工具负责把扶抑与调候分列，避免再次混轴。

## 三、执行批次

### T0 · 测试可复现前置

1. 把 `tsx` 固定为本地 devDependency，`package.json` 测试脚本从 `npx tsx` 改为本地 `tsx`，确保断网时不临时下载运行器。
2. 在改算法前完整跑一次 13 项测试并记录基线；失败则先修测试环境，不带病进入 F0。

**验收**：清空网络能力后仍可用已安装依赖跑完整 `npm test`；package-lock 同步且无无关升级。

### F0 · 金标结构化 + 公式可行性审计（先不改生产判定）

1. 将 22 例的原文金标规范化为独立语义层：`轴=扶抑|调候|混合`、`方向=强|弱|中和|不适用`、原文证据与出处。**不得把算法当前 score/verdict 写进金标文件**。
2. 另建 v3.12 回归快照，存算法基线与“为什么必须守住”的不变量；金标与算法快照物理分离，防止被校方污染校方。
3. 新增只读 runner：批量重排 22 例，输出扶抑、调候、出口与逐项分数；README 对照表由 runner 生成或核对，不再手工抄值。22 例的 v3.12 算法基线只读取冻结的 `regression/v3.12.snapshot.json`，不得从当前生产结果反推。
4. 对三类候选公式做同一网格审计：
   - 地支克泄耗的线性贡献；
   - 两个以上同侧地支、或地支群势与同类透干同现时的非线性协同；
   - 经中立作用裁决后，对帮身分项做柱位归因折损。
5. 候选公式、参数范围与步长必须在首次跑结果前写入审计配置；看到结果后若要扩范围，先记录旧范围为何不足并另起一次审计版本，禁止边看答案边无痕移动球门。
6. 选择顺序固定为：先满足 14✅零回退和 3目标全翻正，再比较 4◐是否恶化，最后取参数最少、非目标案例总绝对分差最小者。做逐例留一敏感性检查与相邻参数检查；“一格参数才过、邻格全坏”视为过拟合，不准入。

**执行结论（2026-08-01）**：v1（1755 格/0 可发）证明普遍补负分会误伤；v2（1755 格/136 格仅过当时方向门）暴露冲次数布尔化且 F2 可取 0 的伪通过；v3（1755 格/0 格过方向+因果门）证明旧步长/宽公式无解；v4（3861 格/1215 格过门）收窄为同支重复和月柱非库冲，但倍率语义仍混；v5（96 格/42 格过门）改成 repeat/echo 互斥，却遗漏 v2 已预注册的总耗方透干门，令李国杰无证据漂移 −2.4；v6（96 格/42 格过门）恢复该门并最终冻结 `repeat=0.4 / echo=1.75 / 生效冲=0.5 / 减力冲=0`。最终 3/3 目标翻弱、14✅零回退、4◐零反向且零恶化、因果门零失败，非目标总绝对分差 4.16；7 个邻格中 4 个可发。留一重选仍有 2/22 改参，顾/阮是小样本关键边界，必须作为已知限制披露。

**边界声明**：22 例同出韦千里，能证明“与该典籍口径的内部一致性”，不能宣称普遍命理准确率。毛盘、三份随包样例、1991 质检盘与旺衰 v2 金标继续作为跨集哨兵，但本版不虚构“盲测集”。

### F1 · 耗方群势入分

1. 总门：年/月/时干至少透出一枚克泄耗干；否则 `耗方群势=0`。该门只证明耗方进入可见结构，不额外加分。
2. 只检查年/日/时三支；仅当完全相同地支重复至少两次且本气属克泄耗时启动，月支不参加分组。每个重复支实例的全部克泄耗藏干按层级权（本气2/中气0.8/余气0.5）×类别权（泄0.5/耗1/克1.5）汇总；不读取三合/三会/半合/半会。
3. 若重复支本气的泄/耗/克类别也在年/月/时干透出，原始单位只乘 `echo_scale=1.75`；否则只乘 `repeat_scale=0.4`。两倍率互斥，不叠加；每个重复支形成一条可追溯审计项。

**主验收**：顾维钧、周信芳翻至弱侧；原 14✅无方向回退；分数账本能解释每一分从哪里来。

### F2 · 冲根修正与数据流重排

1. open 中立裁决先于旺衰；选定流派的 `作用关系.lineage` 仍在后面生成，只供解读，不参与 F2。
2. 本版只有六冲金标，故只有 `type=六冲` 可进入分数；刑、害、破继续展示但不改旺衰，待有独立金标再立项。
3. 只有“冲及月柱”且不属于辰戌/丑未库冲的六冲可入分；库冲和不含月柱的六冲仍留在关系展示中，但不进入分数。
4. 可折损基数严格限定为 `max(0, 得令)+max(0, 长生)`；不折年/日/时得地、不折会局，也不折任何天干基础分或通根加成。
5. 每条规范化物理关系先按柱位+成员生成 canonical ID 去重，再按裁决状态取折损率：`生效=0.5`、`减力=0`、`被解/被绊=0`；同一月柱多条关系累计封顶 100%，贡献不得扣成负数，也不得因伪造/重复外部 ID 重扣。

**主验收**：阮玲玉月日、月时两条巳亥冲有独立 canonical ID，`冲根修正=-6` 且最终偏弱；被解/减力状态、库冲、不含月柱六冲及重复关系均有反例断言。

**证据边界**：直接支持冲根改分的典籍金标只有阮玲玉一例；其他六冲只作接口/回归守门。本版不能外推为“所有六冲必然减根”或通用准确率结论。

### F3 · 双轴校准与出文闭环

1. 校准报告、classics README 与测试摘要统一分列“扶抑强弱”和“调候状态证据”，不再把典籍中所有“弱”字自动映射成扶抑弱。
2. 郑正秋验收锁定现有事实：扶抑可保持强侧；调候必须显示辛/丑命中“有壬乏丙”、盘面火为 0，并在解读输入中保留“寒湿”依据。
3. 不从这一例外推 120 格通用气候分类器；将来若要新增结构化调候状态，必须另有多格金标与独立工单。

**5000 盘执行记录**：首轮曾误用 `interactions=[]` 模拟 v3.12，确认 F1 仍在执行后已将该轮作废并如实留档。有效基线已冻结为 `v3.12.baseline.json` 且与配置 hash 绑定，并以 22 例 v3.12 快照逐案对齐。有效 5000 盘结果：基线五档 287/1939/1694/1030/50，v3.13 为 273/1771/1617/1064/275；当前 confidence high/medium/low=602/2943/1455，low=29.10%；五行单档最大漂移 6.30pp，全部过门。

## 五、铁律与明确不做

1. `calculator/yiqi-core/**` 一字不动；本版允许修改的是 enrich 补层、校准 fixtures、测试与说明文档。
2. 改 `.ts` 后必须 `npm run bundle`；重祝福必须写明旧值为何错、新值为何对。
3. 不把随机盘分布当“准确率”；不把同一作者 22 例包装成跨流派真理。
4. 不做八字海报改版（见 v3.14）、紫微/综合/MBTI、节气深浅词表、评注语译吸收。
5. 不插入“身弱侧降忌权”F4；该项最早另立 v3.15，不能借本版失败顺手扩 scope。
